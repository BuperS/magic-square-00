## Mom Test 결과 *(STEP 1 확정)*

### 페르소나 *(가상)*

프로그래밍 수업(`자료구조`)에서 **4×4 부분 마방진(빈칸 2개)** 과제를 받은 2학년 학생. 손으로 빈칸을 채운 뒤 행·열·대각선 합 34를 검증하고, 이어서 ECB 분류 과제를 제출해야 하는 맥락.

### 진짜 문제 (한 문장)

부분 마방진을 다 맞췄다고 **확신**했지만, 검사해야 할 줄·대각선 중 **하나(부대각선)를 빠뜨린 채** 행·열만 반복 검증했고, 그 **잘못된 “완료” 판정** 위에서 **약 35분**을 허비한 뒤에야 누락을 알게 되었다.

### Mom Test 증거 3줄

1. 「빈칸 두 개에 11이랑 6 넣었고, 네 줄 행이랑 네 줄 열은 손으로 더해서 전부 34 맞는 거 확인했어.」
2. 「그다음부터 행·열만 다시 더하고 빈칸 값을 바꿔 봤는데, **35분 정도** 그렇게만 돌았어.」
3. 「**부대각선**은 아예 안 더했어. 부대각선 더하니까 38이 나와서, 그제야 “아, 검사할 줄을 하나 빼먹었구나” 했어.」

---

## 1) 주제 (한 문장)

> **4×4 부분 마방진에서 “다 맞췄다”고 착각하기 전에, 행·열·대각선 **10개 줄**의 합 34 여부를 빠짐없이 판정한다.**

*(Mom Test: 잘못된 완료 판정·35분 허비 — 솔루션·앱·ECB 전체 구현은 주제에서 제외)*

---

## 2) R-G-I-O

| | 내용 |
|---|------|
| **Role** | 부분 마방진(빈칸 2개)을 손·코드로 채운 **학습자** — “맞는지 확신”하기 전에 검증 누락으로 시간을 쓰지 않으려는 사람 |
| **Goal** | 격자가 **10개 줄**(행 4 + 열 4 + 대각선 2) 모두 합 34인지 **한 번에 판정**하고, 틀린 줄이 **어느 줄인지** 알아낸다 |
| **Input** | 4×4 정수 격자 — 빈칸 2칸이 채워진 상태(예: 11, 6 포함). 각 칸 1~16, 중복·범위 검증은 **이번 세션 범위 밖** |
| **Output** | 줄별 결과 — `{ line_id, sum, pass }` × 10. **하나라도 fail**이면 “완료” 아님. fail 줄 ID(예: `diag_secondary`)를 반환해 **행·열만 반복**하는 루프를 막는다 |

## 3) 성공 기준 3개 *(Mom Test 증거 연결)*

| # | 성공 기준 | Mom Test 증거 | 판정 방법 |
|---|-----------|---------------|-----------|
| **SC1** | **10개 줄**을 모두 검사한다 — **부대각선** 포함, 하나도 생략하지 않는다 | 증거 3 — 「부대각선은 아예 안 더했어」 | `validate_lines` 결과에 `row_*`, `col_*`, `diag_main`, `diag_secondary` **10항목** 존재 |
| **SC2** | 합 ≠ 34인 **줄 ID**를 반환한다 — 값만 바꾸며 행·열만 돌리지 않게 한다 | 증거 2 — 「35분 … 행·열만 …」 | Red 케이스: `diag_secondary` sum=38 → **fail 줄 명시** (행3·열2만 반복하는 패턴 방지) |
| **SC3** | 과제 정답 격자에서 **10줄 모두 pass** — “행·열은 34”만 보고 착각하지 않는다 | 증거 1 — 「행·열 … 34 맞는 거 확인」 *(대각선 미확인 착각)* | Green 케이스: 10줄 pass → “완료” 판정 가능 |

## 4) 표면 문제 — 이번 프로젝트에서 **하지 않을 것**

Mom Test에서 **문제 정의에 쓰면 안 되는** 항목. 세션 3 In Scope **아님**:

| # | 하지 않을 것 | 이유 |
|---|--------------|------|
| 1 | ECB 구조 **전체** 마방진 검증·솔버 프로그램 | 솔루션 선행 — 진짜 문제는 **판정 누락** |
| 2 | GridUI · MissingFinder · **마방진 앱** UI | 표면 문제 — 이번 세션은 **10줄 판정**만 |
| 3 | 빈칸 **자동 탐색·솔버** | “코드로 먼저 풀기” — 검증 **Rule**이 우선 |

## 5) 8계층 — 이번 세션에서 만드는 것

| 계층 | 이번 세션 | 산출물 | Mom Test 연결 |
|------|-----------|--------|---------------|
| **Rule** | ✅ | **10줄 검증 Rule** — 행 4 + 열 4 + 대각선 2, 각 합 **34**일 때만 pass. “행·열만 34” ≠ 완료 | 증거 3 — 부대각선 누락 금지 |
| **Command** | ✅ | **`validate_lines(grid)`** — 4×4 입력 → 10줄 `{ line_id, sum, pass }` + 전체 pass/fail | 증거 2 — **어느 줄**이 틀렸는지 즉시 반환 |
| **(Skill)** | △ 선택 | **검증 체크리스트 Skill** — 10줄 ID를 순서대로 확인했다고 표시 *(Cursor Agent용, 코드 필수 아님)* | 증거 1 — “행·열만 확인” 착각 방지용 **습관** |
| **Test Loop** | ✅ | **Red**: 부대각선 sum=38 격자 → fail + `diag_secondary` 명시 · **Green**: 10줄 pass 격자 | 증거 2·3 — 같은 실패·성공 **재현** |
| Hook | ❌ | — | 세션 3 제외 |
| MCP | ❌ | — | 세션 3 제외 |
| ARRR | ❌ | — | 세션 4+ |
| Entity/Control/Boundary 전체 | ❌ | — | 세션 4+ |

### Rule (초안)

```
RULE-VAL-01: 4×4 격자의 각 행(4)·열(4)·주대각선·부대각선 — 총 10줄 —
             각 줄의 합이 34일 때만 해당 줄 pass.
RULE-VAL-02: 10줄 중 하나라도 fail이면 "완료" 판정 금지.
RULE-VAL-03: fail 시 반드시 line_id를 반환한다 (행·열만 무작정 재시도 금지).
```

### Command (초안)

```
/validate-lines — 4×4 격자 JSON/배열 입력 → 10줄 검증 결과 출력
```

### Test Loop (케이스 초안)

| 케이스 | 기대 | Mom Test |
|--------|------|----------|
| **Red-T1** | 부대각선 sum=38, `diag_secondary` fail | 증거 3 재현 |
| **Green-T1** | 10줄 모두 sum=34, all pass | 증거 1 착각 방지 |
