## 4. 빠짐·어긋남 판정 *(7건)*

| # | 구분 | 계약 (§5) | R-G-I-O / SC | 문제 |
|---|------|-----------|--------------|------|
| 1 | **Output** | 10줄 + **전체 pass/fail** (§5 Command) | `{ line_id, sum, pass }` ×10 + “하나라도 fail이면 완료 아님”(개념)만 | **집계 pass/fail 필드**(`ok` / `all_pass` / `status` 등)가 Output 스키마에 없음 |
| 2 | **Output** | 10줄 **전부** 반환 (Command) | “fail 줄 ID … **반환**” | fail 줄만 돌려주는 것처럼 읽힘 — ×10 전체 반환과 **문구 충돌** |
| 3 | **SC1** | 줄마다 `{ line_id, sum, pass }` | `row_*` … **10항목 존재**만 검증 | **`sum`·`pass` 필드** 존재·값 검증 없음 |
| 4 | **SC1** | 예시 ID `diag_secondary` | `row_*`, `col_*` 와일드카드 | **`row_0` vs `row_1`** 등 인덱스 규약 미고정 → SC1 판정 기준 모호 |
| 5 | **SC2** | 줄별 `{ line_id, sum, pass }`; Red-T1 **sum=38** | “fail 줄 **명시**”만 | **`sum=38` 검증** 누락 (Test Loop Red-T1과 SC2 판정 방법 불일치) |
| 6 | **SC2** | RULE-VAL-02 + **전체 pass/fail** | fail **줄 ID**만 | Red에서 **집계 fail/미완료** 미검증 |
| 7 | **SC3** | **전체 pass/fail** + 10줄 pass | “10줄 pass → 완료 판정 **가능**” | **집계 pass/fail API**를 SC3가 요구하지 않음 |

**일치 확인:** 4×4 입력, 10줄(행4+열4+대각2), 합 34, `diag_secondary` Red, 10줄 Green, fail 시 줄 식별 — Goal·SC 방향은 계약과 정합.
